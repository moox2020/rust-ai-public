概念一 · 类型系统里的诚实

Result<T, E>——没有 null，只有两条明说的路

Rust 没有异常、没有 null 指针；一个可能失败的函数，返回值本身就写明了两种可能。

枚举定义
enum Result<T, E> {
  Ok(T),
  Err(E),
}
  • ·编译器强制两条分支都被处理，忘记处理编译不通过。
  • ·调用大模型 API 的函数，返回类型几乎都是 Result<T, E>。
03 / 08CONCEPT · RESULT<T,E>
概念二 · 消灭样板代码

? 操作符——遇到 Err 就自动"短路上抛"

不用逐层 match，一个问号让错误沿调用链自动向上传递。

  • ·expr? 等价于：Ok 就取值继续，Err 就直接 return——省掉手写 match。
  • ·错误沿函数调用链逐层上抛，直到某一层显式处理（通常是 main）。
04 / 08CONCEPT · ? OPERATOR
概念三 · 统一混乱的错误类型

anyhow——把各种错误收进同一个口袋

reqwest 的错误、serde_json 的错误、你自己的业务错误——类型各不相同，应用层不该逐一关心。

  • ·业务函数统一返回 anyhow::Result<T>，不必逐一定义错误枚举。
  • ·.context() 像贴便签一样，给错误加人类可读的上下文。
  • ·println!("{:#}", err) 打印完整的错误链路，方便排查。

06 / 08ARCHITECTURE · ERROR PIPELINE
代码实操 · 场景说明

实战场景：AI 配置加载与调用的容错骨架

四个函数、三种可能失败的环节，一次串起 Result、? 和 anyhow 的完整协作方式。

STEP 1
加载配置
从 JSON 字符串反序列化出 API Key 与模型名，格式错误即失败。
Result<AiConfig>
STEP 2
校验配置
API Key 为空则视为无效配置，主动 bail! 出一个错误。
Result<()>
STEP 3
调用 AI 接口
模拟一次补全请求；prompt 为空视为业务错误。
Result<String>
STEP 4
统一收口
main 里用 ? 串联前三步，成功打印结果，失败打印完整错误链。
anyhow::Result<()>
  • ·三个环节各自独立，任何一环失败都不会污染后续步骤的数据。
  • ·全程不写一次 match，只用 ? 与 .context()。
  • ·这就是第13-20节接入真实大模型 API 时会直接套用的错误处理形状。
